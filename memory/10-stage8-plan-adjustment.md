- 位置：队列 14（R11 cutover + 旧路径断流）完成之后、正式三轮回环之前。
- 条件：使用队列 16 冻结的固定四节点 clients 配置（不得更换 workload/judge/clients 扫描结果）。
- 动作：跑 **单轮**；要求零 error/timeout/forced-cancel/zero-op、RC=0、natural close；
  记录该轮 aggregate TPS 读数。
- 判据（三档）：
  1. **正确性红**（任一错误类 > 0）→ 不得消耗正式回环；按 8-G.2 归因（只有证明某 R
     新引入回归才回滚该 R），修复后重采；
  2. **正确性绿但 TPS < 1116.25** → 判定机制替换未带走塌陷 / 性能底材不足，
     **R16/R17 接棒**（见 §2），正式三轮回环顺延至 R17 之后；

- 判据 2 的充分性论证：正式门要求三轮中位数 > 1116.25，且历史跨轮单调塌陷
  （首轮即最高轮），故"首轮 ≥ 1116.25"是正式门可行的必要条件——采样不过，
  正式回环必然无望，提前接棒只省时间、不降标准。

## 2. R16/R17 接棒位（队列延伸 + 触发条件）

触发条件（任一）：

- A. G-TPS-R11 采样 TPS 红（正确性绿但 < 1116.25）；
- B. 正式三轮回环 TPS 红（中位数 ≤ 1116.25，或跨轮波动复现塌陷形状）——
  不原样重跑，直接接棒；
- C. 正确性红且归因指向 A1–A4 域（buffer-version / PI lifecycle、undo segment、
  CR 专用池派生链）。

接棒后的顺序（与 A-9 一致）：

```
R16（A1+A3：buffer-version / PI lifecycle + 统一 buffer cache + 原子退役 CR 专用池）
  → R17（条件式 A2 + A4 follow-through + R4A 迁移/退役核验）
  → 最终正式 verdict（三轮零错 + 中位数 > 1116.25，判据不变，仅在 R17 后执行）
```

- 触发 A/C 时跳过中间重试、直接进入 R16/R17；触发 B 时不重复烧正式回环。
- R17 后正式回环仍红 → 计划内资源用尽；唯一出口 = 重开 A-campaign 根因调查
  （user"停查"裁决的复审），需 user 显式开门，计划不自动开启。
